# 01. 要件定義 — 何を作り、何を作らないか

## 1. このアプリの目的

**自分のやることを書き留めて、終わったかどうかを管理する** ためのアプリ。

---

## 2. スコープ（作る範囲）

### ✅ 作るもの（このアプリでやること）

1. **タスクの追加** … 入力欄に文字を打って、リストに追加できる
2. **一覧表示** … 追加したタスクを一覧で見られる
3. **完了チェック** … 終わったタスクにチェックを付けられる（チェックを外すこともできる）
4. **タスクの削除** … いらなくなったタスクを消せる
5. **タスクの編集** … 追加済みタスクの文字をあとから直せる

### ❌ 作らないもの（今回はやらないこと）

- ログイン・ユーザー登録（認証）
- 期限、カテゴリ、優先度、並び替え、検索
- スマホアプリ化

### 🔜 次のフェーズで扱うこと

- **サーバー・データベースとの通信によるデータ保存**

今回のフェーズでは **フロントエンドを作り切ること** が目標。

- データはブラウザ内（localStorage）に保存する
- サーバー連携は **フロントが完成したあとの次フェーズ** で追加する予定

---

## 3. 機能要件

### F-1. タスクの追加

- 画面に入力欄と「追加」ボタンがある
- 文字を入力して追加すると、リストの一番下（または上）に新しいタスクが表示される
- **空文字（何も入力していない状態）では追加できない**
- 追加したら、入力欄は空に戻る

### F-2. 一覧表示

- 追加済みのタスクがすべて縦に並んで表示される
- 各タスクには「チェックボックス」と「タスクの文字」が表示される
- タスクが1件もないときは「タスクがありません」のような案内を表示する

### F-3. 完了チェック

- 各タスクのチェックボックスを押すと、完了／未完了が切り替わる
- 完了したタスクは、見た目でわかるようにする（例：文字に打ち消し線）

### F-4. タスクの削除

- 各タスクに「削除」の操作（ボタンなど）がある
- 押すと、そのタスクが一覧から消える

### F-5. タスクの編集

- 各タスクの文字を、あとから書き換えられる
- 編集して確定すると、一覧の表示も更新される
- **空文字には編集できない**（F-1と同じ考え方）

---

## 4. 非機能要件

| 項目               | 決めたこと                       | 理由                                                         |
| ------------------ | -------------------------------- | ------------------------------------------------------------ |
| データの保存先     | ブラウザの **localStorage**      | 今回はフロントエンドのみのフェーズで、サーバーを使わないから |
| データが消える条件 | ブラウザのデータを消すと消える   | localStorageの仕組み上そうなる                               |
| 対応環境           | PCの新しめのブラウザ（Chrome等） | まずは1環境で動けば十分だから                                |
| 見た目             | 最低限、読みやすければOK         | まずは動くことを優先するから                                 |

---

## 5. ユーザーストーリー（使う人の目線）

- 「やることを思いついたので、**さっと入力して追加** したい」
- 「今日やることが **一覧でパッと見られる** と安心する」
- 「終わったタスクに **チェックを付けて、達成感** を得たい」
- 「もう不要になったタスクは **消して** すっきりさせたい」
- 「打ち間違えたタスクを **あとから直したい**」

---

## まとめ

- 作るのは **追加・一覧・完了チェック・削除・編集の5つ**
- データは **ブラウザのlocalStorage** に保存する
- 認証や期限などは今回のスコープ外
- **サーバー・DB連携は次フェーズ**。今回はフロントエンドの完成が目標
