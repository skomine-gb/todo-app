# 05. ディレクトリ構成と実装の進め方

## 1. ディレクトリ構成

`src` と `test/` の中身が実装対象。フェーズ2（バックエンド）に向けて、`src` はフロント（`front/`）・サーバー（`server/`）・共有（`shared/`）の3つに分かれている。

```
todo-app/
├── docs/                      ← 設計ドキュメント
├── src/
│   ├── front/                 ← React SPA（フロントエンド）
│   │   ├── main.tsx           ← 起動エントリ（用意済み）
│   │   ├── App.tsx            ← 全体のまとめ役コンポーネント
│   │   ├── style.css          ← 見た目（CSS）
│   │   ├── hooks/
│   │   │   └── useTodos.ts    ← 状態保持 + 永続化 + 各操作
│   │   └── components/
│   │       ├── TodoInput.tsx  ← 入力欄・追加ボタン
│   │       ├── TodoList.tsx   ← 一覧のまとめ役
│   │       └── TodoItem.tsx   ← タスク1件（完了・編集・削除）
│   ├── server/                ← Hono の API Worker（バックエンド）
│   │   ├── index.ts           ← basePath("/api") でルートをまとめる
│   │   └── routes/            ← エンドポイントごとのルート定義
│   └── shared/
│       └── types.ts           ← front / server で共有する型（Todo 型）
└── test/worker/               ← バックエンドのテスト（Workers ランタイム）
```

分け方の考え方：

- **`front/` と `server/` を分ける**：ブラウザで動くコードと Cloudflare Workers（サーバー側の実行環境）で動くコードは、動く場所も使える機能も違うため、フォルダで境界をはっきりさせる
- **`shared/` に型を置く**：`Todo` 型はフロントもサーバーも使う。どちらか一方に置くと逆側から参照しづらくなるため、両方から見える場所に集約する
- **フロントの中は役割ごと**：部品は `components/`、状態の仕組みは `hooks/`
- **バックエンドのテストだけ `test/worker/`**：フロントのテストは実装と同じ場所（コロケーション）に置くが、バックエンドのテストは Workers ランタイム（Cloudflare 上と同等の実行環境）で動かす設定が別に必要なため、専用フォルダに分ける

## 3. 実装ルール

全STEP共通で守る方針。

- **小さく作って動かして確認**：機能を1つ作るごとに動かして確認し、土台から順に進める
- **実装とテストはセット**：実装したコードには対応するテストコードを必ず併せて書く。`vp test` が通って初めてそのSTEPを完了とする

## 4. 実装ステップ

```mermaid
flowchart TD
    S1["STEP 1: 型<br/>types.ts に Todo 型"] --> S2["STEP 2: 一覧表示<br/>仮データを画面に出す"]
    S2 --> S3["STEP 3: 追加"]
    S3 --> S4["STEP 4: 完了チェック"]
    S4 --> S5["STEP 5: 削除・編集"]
    S5 --> S6["STEP 6: 永続化<br/>useTodos で localStorage 対応"]
    S6 --> S8["STEP 8〜12: バックエンド<br/>（フェーズ2。09 参照）"]
    S8 --> S7["STEP 7: 仕上げ<br/>0件表示・見た目調整"]
```

| STEP | 状態     | 内容                                                      | 併せて書くテスト                                                | 対応要件  |
| ---- | -------- | --------------------------------------------------------- | --------------------------------------------------------------- | --------- |
| 1    | ✅ 完了  | `types.ts` に `Todo` 型を定義                             | —（型定義のみ）                                                 | —         |
| 2    | ✅ 完了  | 仮データを `TodoList` / `TodoItem` で表示                 | 渡したタスクが表示される／0件時に案内が出る                     | F-2       |
| 3    | ✅ 完了  | `TodoInput` で追加。空文字は不可                          | 追加で件数が増える／空文字は追加されない                        | F-1       |
| 4    | ✅ 完了  | チェックで `completed` 切替、完了は打消線                 | 対象の `completed` が反転する                                   | F-3       |
| 5    | ✅ 完了  | 削除ボタンで除去、編集で `title` を書き換え（空文字不可） | 削除で対象が消える／編集で `title` が変わる／空文字にはできない | F-4 / F-5 |
| 6    | ✅ 完了  | 状態と保存を `useTodos` に集約、再読込でも残す            | 保存後に読み込むと一覧が復元される                              | 永続化    |
| 7    | ⏸ 後回し | 0件時の案内、`style.css` で見た目調整                     | 0件時の表示（STEP2のテストで担保）                              | F-2       |

STEP 7（仕上げ）は番号を残したまま **フェーズ2（STEP 8〜12。[09](./09-backend-steps.md)）のあとに実施する**。見た目の大部分は STEP 2〜5 で先行して整えたため急ぎではなく、先にバックエンドへ進む方が学習効果が高いと判断した。

各STEPの終わりに `vp test`（テスト）と `vp dev`（ブラウザ確認）の両方を行う。

## 5. 検証コマンド

| コマンド             | 内容                                                                   |
| -------------------- | ---------------------------------------------------------------------- |
| `vp dev`             | 開発サーバーを起動しブラウザで確認（SPA + API を同時起動）             |
| `vp check`           | 整形・Lint・型チェック                                                 |
| `vp test`            | フロントエンドのテスト実行（jsdom）                                    |
| `vp run test:worker` | バックエンドのテスト実行（Workers ランタイム）                         |
| `vp run cf:preview`  | 本番相当の確認（ビルドして `wrangler dev` で起動。Static Assets 込み） |

最初に `vp install` → `vp dev` で開始する。環境に不調があれば `vp env doctor`。

## 6. 完成チェックリスト

[01 の機能要件](./01-requirements.md#3-機能要件) との対応：

- [ ] 文字を入力して追加すると一覧に増える（F-1）
- [ ] 空文字では追加できない（F-1）
- [ ] 追加済みタスクがすべて表示される（F-2）
- [ ] 0件のとき案内が表示される（F-2）
- [ ] チェックで完了／未完了が切り替わり、見た目が変わる（F-3）
- [ ] 削除でタスクが一覧から消える（F-4）
- [ ] 編集で内容を書き換えられる。空文字にはできない（F-5）
- [ ] 再読み込みしてもタスクが残る（永続化）
- [ ] 各機能にテストコードがあり、`vp test` が通る
