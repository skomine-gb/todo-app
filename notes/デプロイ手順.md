# デプロイ手順（Cloudflare への公開）

> これは **提出しない個人用のメモ** です。本番公開の手動手順を、あとで迷わないようにまとめています。
> **現在は main へのマージで GitHub Actions が自動デプロイする**（[docs/10-ci-cd.md](../docs/10-ci-cd.md)）。このメモは初回セットアップとトラブル時の切り分け用。設計は [docs/06-backend-architecture.md](../docs/06-backend-architecture.md) §5、DB まわりは [docs/07-db-schema.md](../docs/07-db-schema.md) を参照。

---

## 前提（1回だけやること）

- Cloudflare アカウントを作成しておく（無料プランで足りる）
- `wrangler login` でブラウザ認証を済ませる（`wrangler whoami` で確認できる）

## 手順

1. **本番用の D1 データベースを作る**（まだ作っていなければ）

   ```sh
   wrangler d1 create todo-app-db
   ```

   出力に `database_id` が表示されるので控える。

2. **`wrangler.jsonc` に `database_id` を設定する**

   `d1_databases` の `database_id` を手順1の値にする。binding を変更した場合は `vp run types` で `worker-configuration.d.ts` を再生成してコミットする。

3. **マイグレーションを本番の D1 に適用する**（通常は main へのマージで自動適用される）

   ```sh
   vp exec wrangler d1 migrations apply DB --remote
   ```

   `--remote` が本番向け。付けないとローカルにしか適用されないので注意。`DB` は wrangler.jsonc の binding 名（データベース名の書き写しより安全。docs/10 §4）。

4. **本番相当の動作確認**

   ```sh
   vp run cf:preview
   ```

   ビルドして `wrangler dev` で起動する（Static Assets の配信込み）。ここで一通り触って問題ないことを確認してからデプロイする。

5. **デプロイ**

   ```sh
   vp run deploy
   ```

   ビルドして `wrangler deploy` が実行され、表示された URL（`*.workers.dev`）で公開される。

## デプロイ後の確認チェックリスト

- [ ] 公開 URL で画面が表示される（SPA が配信されている）
- [ ] `<公開URL>/api/health` が `{ "status": "ok" }` を返す
- [ ] 追加・一覧・完了チェック・削除・編集の5機能が動く
- [ ] 再読み込み・別ブラウザでもタスクが残っている（本番 D1 に保存されている）

## 注意メモ

- ローカルの D1（`.wrangler/state/` 配下）と本番の D1 は **別物**。ローカルで入れたタスクは本番には出てこない
- テーブル定義を変えたら、新しいマイグレーションを作って **ローカル（`--local`）と本番（`--remote`）の両方に** 適用する
- 認証を付けていないので、URL を知っていれば誰でも読み書きできる状態になる。公開範囲には注意（必要になったら次のフェーズで認証を検討）
